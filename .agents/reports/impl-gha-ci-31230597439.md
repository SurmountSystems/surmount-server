## Root cause

`HelperNftClient::roundtrip_process` spawns a fake helper script, writes JSON on stdin, then waits for stdout.

The test fake scripts were:

```sh
#!/bin/sh
echo '{"ok":true}'
```

They never read stdin. On a loaded CI runner the shell can exit and close the pipe **before** the parent finishes `write_all`, so the parent gets `EPIPE` / Broken pipe and the test unwrap panics.

This is a race (often green locally; red under GHA parallelism / scheduling). The real helper uses `apply-json` + full stdin drain (`read_to_string`), so product helpers do not intentionally close early; only racey fakes did.

## Fix

File: `crates/management-ui/src/nft_helper.rs`

1. **Fake scripts** (ok + refuse paths, including `enforce_helper_refuse_leaves_memory_unbanned`): drain stdin before answering:

   ```sh
   #!/bin/sh
   cat >/dev/null
   echo '...'
   ```

   Matches the real `apply-json` contract (read request, then respond) and removes the race.

2. **Client resilience:** on process stdin write, ignore only `ErrorKind::BrokenPipe` and continue to `wait_with_output` + fail-closed JSON parse. Other write errors still fail closed. Response parsing remains the authority for success/refuse.

No CI workflow or flake path changes. No secrets, no git mutation.
